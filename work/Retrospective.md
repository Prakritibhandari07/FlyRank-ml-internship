Retrospective — FlyRank ML Internship Capstone
When I began this internship in Week 1, my goal was simple: learn how to build a machine learning model that could solve a real problem. I expected the focus to be on algorithms, accuracy, and code. My mindset was very technical — I thought success meant “train a model that beats the baseline.” What I didn’t realize then was that the real challenge, and the real learning, would be about the workflow and communication that surround the model. Over the weeks, my perspective shifted from “just code” to “end‑to‑end system design and storytelling.”

Early on, I set out to tackle FlyRank’s content ranking problem using anonymized production data. The case study was clear: long‑tail queries often fail to surface relevant results, and improving ranking here could make a real difference. I thought the hardest part would be choosing the right algorithm. Instead, I discovered that framing the problem correctly, cleaning the data, and building a transparent baseline were just as important. By Week 3, I had learned that reproducibility and clarity matter more than chasing a few extra points of accuracy.

One of the biggest changes in my approach was realizing that documentation and demos are part of the build. At first, I saw README files and demo scripts as “extras.” But as the assignments progressed, I understood that universities, employers, and reviewers judge your work through what they can see and run themselves. A stranger should be able to clone my repo, follow the README, and reproduce my results. That discipline forced me to think about my project as a product, not just an experiment. It also made me more honest about limitations — because hiding them in code doesn’t help anyone, but naming them in a README builds credibility.

Another change was how I used AI assistance. I leaned on Copilot and Claude to help draft documentation, abstracts, and summaries. But I always verified the technical steps myself. This balance taught me that AI can be a career partner: it accelerates writing and framing, while I remain responsible for correctness. Saying “I built this with AI help, and here’s what I checked myself” is not weakness — it’s transparency. That posture is something I’ll carry forward.

Looking ahead, the next build I’d pursue is extending the ranking model to handle rare queries more effectively. Sparse data is the limitation I kept running into. Embedding‑based approaches or hybrid models could help. I’d also like to deploy a lightweight API so others can interact with the model directly, and add monitoring to track performance drift. These steps would make the project more practical and closer to production use.

Three transferable lessons stand out. First, reproducibility: making sure anyone can run my work from the README alone. This skill applies to any research or engineering role. Second, honest evaluation: showing both gains and limitations builds trust. Employers and universities value transparency more than inflated claims. Third, communication: writing abstracts, demo outlines, and shareable posts taught me how to frame technical work for different audiences — technical peers, employers, and the public. That’s a skill I didn’t expect to practice, but it’s one of the most valuable outcomes.

Reflecting specifically, I see how my mindset changed. At first, I thought machine learning was just about training models. Now I understand it’s about system design, workflow discipline, and storytelling. I became more consistent in committing work, documenting clearly, and thinking about the audience. I also became comfortable using AI as a thinking partner, not a crutch. That shift — from “just code” to “code + communication + credibility” — is the biggest transformation in how I work.

This capstone is the first real thing I’ve shipped end‑to‑end. It proves I can take a messy problem, build a working ML solution, document it, and present it honestly. That’s the skillset I’ll carry into applications, interviews, and future builds. More than the model itself, the retrospective shows how I grew: from a student focused on accuracy to a builder focused on reproducibility, transparency, and communication. That’s the story I’ll tell going forward.
